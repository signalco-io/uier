# Managed project monitor

A uier-orchestrator worker runs the same triage, ownership, fix, PR and deploy workflow as any project monitor. Its supervisor supplies wake delivery and stops it when the workload drains. Follow these overrides on the first turn and every subsequent wake, including delegate and PR notifications.

1. Resolve the installed orchestrator helper at `<UIER_MONITOR_HOME or ~/.uier-monitor>/orchestrator/orchestrator.mjs`. Work in the enrolled checkout. For a managed start or tick run `node <helper> enter <projectId> <run>` before touching state, assigning anything or arming a watcher. In T3 or Codex pass your actual session ID as the last argument when the harness omits its thread ID environment variable. If it refuses, end the turn. A persisted `state.orchestrator.run` identifies managed work on context resets and ordinary wakes as well.
2. Match `list_projects.actingAs.userId` to the account returned by `enter` and the watcher token's identity. If they differ, stop and report the account mismatch. Use the enrolled scope and account. A saved monitor that also includes other accounts needs its owner to reconcile the scope before continuing. Install the monitor helper as usual. `first: true` means run the full First start even though the handshake created a minimal state file. On a resume preserve the saved repository restrictions and routing. Fetch and re-triage every ID in the handshake’s `recheck` list, including saved skips and reopened Done items. Read their current packets, preserve any completed writes, and remove IDs from `orchestrator.recheck` with `M patch` after recording their decisions.
3. Use `M watch --persistent --inbox-only --detach` for waiting on **all three harnesses**. On a first handoff replace an incompatible watcher only after verifying ownership. The supervisor delivers the inbox to your session. Disable old fallback schedules for this monitor. Do not create model-poll schedules, run another waiting loop, or self-send context resets in this mode. Consume even quiet closing events (including their archive work). On native CLI turns, complete and record pending native agents' results before returning so ending the CLI turn cannot strand a delegate.
4. A **managed retirement** message is a separate path from a start or tick. Read project state first; require `stopped`, `watch.stoppedBy === "orchestrator:" + run` and the matching `state.orchestrator.run`. In T3 also verify your current thread ID equals the recorded monitor thread. Leave session slots, disable the monitor's schedules, unwatch its PRs, clear `harness.pinnedAt`, then unpin and settle this thread with `t3_thread_organize`. End the turn. The supervisor verifies T3's settled state; native sessions settle by exiting after their last turn.
5. A person's project **stop** uses the normal stop path and writes `watch.stoppedBy: "person"`, even if the monitor is already parked. A person's explicit standalone start/takeover clears `state.orchestrator` before resuming. The next supervisor scan relinquishes that worker.
